# Changes — v2.3.0 (2026-04-30)

> Premier release notes packagé après deux jours de tests intensifs sur une vraie app React Native (Pawfect Travels). Ces changements répondent à des frictions concrètes observées en pratique, pas à des suppositions théoriques.

## TL;DR

- 🆕 **2 nouveaux tools** : `prepare_device`, `dismiss_keyboard`
- ✨ **Auto-prepare device** au `set_device` (opt-out via `skip_setup: true`)
- 🛡️ **Auto-dismiss keyboard** dans `tap` quand la cible est masquée par le clavier
- 🔍 **`type_text` verify opt-in** : détecte les autocomplete-pickers qui interceptent les keystrokes
- 📚 **3 nouveaux docs** : `LIMITATIONS.md`, `PATTERNS.md`, `FEATURE_REQUESTS.md`
- 🧰 **Aucun breaking change** — backward compatible 100%

## Pourquoi ces changements ?

Pendant deux jours de tests E2E sur une app React Native Expo (~50 sub-phases, 56 bugs trouvés, 5 voyages générés), trois frictions sont revenues en boucle :

1. **Status bar / clipboard / keyboard sales** entre sessions → tests instables, faux positifs
2. **Tap qui rate** parce que le clavier ouvert masquait la cible
3. **`type_text("Paris")` produit "av"** car un picker d'autocomplete intercepte les keystrokes

Tous ces problèmes ont des workarounds connus, mais ils tuent la productivité quand on les hit pour la 5ᵉ fois en une session. Cette release les adresse à la racine.

## Nouveaux tools

### `prepare_device`

Prépare le device actif pour une session de test propre :
- Dismiss le clavier s'il est visible
- Clear le clipboard
- Reset les overrides de status bar (iOS)
- Force keyboard QWERTY (iOS, sécurité contre AZERTY locales)

Tout est opt-out via flags individuels :

```typescript
prepare_device({
  dismiss_keyboard: true,    // default true
  clear_clipboard: true,     // default true
  clear_status_bar: true,    // default true (iOS only)
  force_qwerty: true,        // default true (iOS only)
})
```

Chaque step est best-effort : un échec sur un step ne bloque pas les autres.

### `dismiss_keyboard`

Ferme le clavier sur le device actif. No-op si pas de clavier visible.

```typescript
dismiss_keyboard()
```

iOS : détecte `XCUIElementTypeKeyboard`, tap au-dessus de ses bounds.
Android : envoie `KEYCODE_ESCAPE` (cleaner que `BACK`), avec `BACK` en fallback.

À utiliser :
- Après un `type_text` quand le clavier bloque les boutons en bas
- Avant un screenshot pour ne pas avoir le clavier dans la photo
- Avant une assertion qui dépend d'un élément masqué par le clavier

## Améliorations des tools existants

### `set_device` — auto-prepare

Le `set_device` appelle maintenant `prepare_device` automatiquement la première fois. Opt-out via `skip_setup: true` :

```typescript
set_device({
  device_id: "...",
  skip_setup: false,   // default false → auto-prepare
})
```

**Migration** : aucune action requise. Si tu avais des screenshots demo avec un statusbar override custom (`9:41 AM`), passe `skip_setup: true` pour préserver l'override.

### `tap` — auto-dismiss keyboard si bloque

Le `tap` détecte maintenant si la cible (coords ou index) est physiquement dans la zone du clavier visible. Si oui, dismiss le clavier d'abord puis tap.

```typescript
tap({
  index: 42,
  auto_dismiss_keyboard: true,   // default true
})
```

**Comportement conservateur** : si la cible est *au-dessus* du clavier, on ne touche à rien. Si la cible tape sur une touche du clavier elle-même (cas de test rare), passe `auto_dismiss_keyboard: false` pour le permettre.

**Migration** : aucune action requise. Le comportement par défaut est plus robuste, pas plus aggressif.

### `type_text` — `verify` opt-in

Nouveau paramètre `verify: true` qui re-lit le champ après le type pour confirmer la valeur :

```typescript
type_text({
  text: "Paris",
  element_text: "departure-input",
  verify: true,   // default false (opt-in pour éviter le coût)
})
```

Détecte les cas où :
- Un picker d'autocomplete intercepte les keystrokes
- Le focus n'était pas sur le bon champ
- Le pbcopy+paste a échoué silencieusement

**Coût** : ~150-200ms supplémentaires (pour laisser l'autocomplete s'animer + un fetch de la valeur).

**Migration** : aucune action requise. Le default `verify: false` préserve le comportement v2.2.

## Note sur la philosophie de test

Cette release packagée a été produite avec une règle stricte d'**analyse-only** : pendant les sessions de test qui ont nourri ces changements, **aucun bug d'app n'a été corrigé directement**. La méthodo a été :

1. **Phantom MCP UI test** → trouve les bugs visuels et de flow
2. **Code review fallback** → confirme la présence d'une feature quand l'UI est bloquée
3. **DB query fallback** → confirme la persistance / l'état réel quand l'UI ment

Cette discipline a permis de trouver 56 bugs en deux jours sans introduire de régressions, et de produire un BUGS.md propre dispatchable en équipe.

Voir [PATTERNS.md](PATTERNS.md) section "DB query > UI scan pour audits massifs" pour l'esprit.

## Internals (pour les contributeurs)

### Helpers ajoutés

**iOS** (`src/platforms/ios/`)
- `simctl.ts` :
  - `iosClearClipboard(udid)` — vide le clipboard simulateur
  - `iosClearStatusBar(udid)` — `simctl status_bar clear`
  - `iosForceKeyboardQwerty(udid)` — `defaults write -g AppleKeyboards`
- `wda.ts` :
  - `iosIsKeyboardVisible()` — check `XCUIElementTypeKeyboard` dans la source
  - `iosGetKeyboardBounds()` — extrait les bounds `x/y/width/height`
  - `iosDismissKeyboard()` — tap au-dessus du keyboard, vérifie qu'il est dismiss

**Android** (`src/platforms/android/adb.ts`)
- `androidIsKeyboardVisible()` — check `mInputShown=true` via `dumpsys input_method`
- `androidDismissKeyboard()` — `KEYCODE_ESCAPE` puis fallback `KEYCODE_BACK`
- `androidClearClipboard()` — `service call clipboard 2`
